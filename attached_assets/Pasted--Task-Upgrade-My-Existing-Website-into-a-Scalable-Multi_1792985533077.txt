# Task: Upgrade My Existing Website into a Scalable Multi-Platform Video Downloader Platform

Act as a senior product designer, UI/UX engineer, frontend architect, and monetization-focused web designer.

I have already built the initial UI/UX design for a video downloader website using Replit. Modify the EXISTING project to support a scalable, multi-platform video downloader experience.

Do not create a completely new project or discard my existing design. Inspect the current project first, preserve its visual identity, and improve its structure, layout, components, and user experience.

The long-term vision is to build one website where users can paste a video URL from a supported platform, view available download options, select a quality, and download the video when a legitimate and authorized download source is available.

Potential platforms include:
- Facebook Reels and Facebook videos
- YouTube
- TikTok
- Instagram Reels and videos
- X (Twitter) videos
- Pinterest videos
- Reddit videos
- Other platforms that may be supported in the future

Important: These platforms do not all permit the same downloading methods. Do not imply that every platform is currently supported or that every video is downloadable. The interface must distinguish between implemented, planned, and unavailable integrations. Respect platform terms, copyright, access controls, and applicable API restrictions.

My business goals are:
1. Build a scalable multi-platform website.
2. Attract organic traffic through SEO.
3. Prepare dedicated advertising placements for future Google AdSense integration.
4. Keep the design professional, mobile-friendly, fast, and easy to maintain.

## 1. Preserve and Improve the Existing Design

First inspect the existing Replit project, its routes, components, styling, and dependencies.

Keep the existing design wherever possible.

Improve the design to make it feel like a polished, modern SaaS utility platform.

Design direction:
- Clean white or light-neutral background.
- Deep navy typography.
- A consistent blue accent color.
- Subtle borders and shadows.
- Rounded cards and input fields.
- Generous whitespace.
- Consistent Lucide icons.
- Excellent mobile responsiveness.
- Clear typography and visual hierarchy.

Avoid clutter, excessive gradients, unnecessary animations, misleading download buttons, and intrusive popups.

Keep the brand name and visual tokens configurable so the brand can be changed later.

## 2. Create a Multi-Platform Homepage

Update the homepage to support multiple video platforms rather than appearing to be exclusively a Facebook downloader.

Suggested headline:

"Download Videos from Supported Platforms"

"Paste a video link to explore available download options in one simple interface."

The hero section should include:

- A paste-from-clipboard button.

- A loading state.
- A clear validation and error area.

If automatic platform detection fails, display a clear error and a link to supported-platform information.

Do not display a successful video result until an actual provider response confirms it.

Each platform entry should support fields such as:

- icon

- status
- availability message
- optional guide URL
- optional brand accent configuration

Use explicit statuses such as:
- Available
- Planned
- Unavailable

Only mark a platform as Available when its integration is genuinely implemented and tested.

Planned integrations must not appear to be working download services.

Use this registry to power:
- Platform cards.
- Supported-platform lists.
- Platform selection controls.
- URL platform detection.
- Platform-specific help text.
- Future platform landing pages.

Do not place the entire implementation in one large component.

## 7. Add Google AdSense Placeholder Slots

I intend to apply for Google AdSense later.

For now, add visually distinct DEMO AD PLACEHOLDERS to the layout in sensible locations. These must be placeholders, not real advertisements.

Create a reusable AdSlot component with properties such as:
- id
- placement
- format
- responsive
- enabled
- label

Supported placements should include:
- Top banner, below the header.
- In-content banner, between major homepage sections.
- Sidebar advertisement on suitable desktop layouts.
- A reserved area below video results.
- A footer-adjacent placement, where appropriate.

Recommended desktop formats may include:
- Responsive display.
- Leaderboard-style placeholder.
- Medium rectangle-style placeholder.

On mobile, use responsive full-width placeholders with appropriate spacing and no horizontal overflow.

Do not show every ad slot simultaneously if doing so would overwhelm the user. Use a restrained layout with sufficient content and whitespace.

### Ad Placeholder Appearance

During development, display a neutral placeholder with:
- A subtle dashed border.
- A light-neutral background.
- A small "Advertisement" label.
- A small "Ad placeholder — development only" caption.
- A simple illustrative icon if appropriate.

Use realistic reserved dimensions for layout planning, but do not pretend the placeholder is an actual ad.

The placeholders must not:
- Look like Download buttons.
- Be clickable advertisements.
- Simulate ad clicks.
- Contain fake advertisers or promotional claims.
- Obstruct the main download workflow.
- Trigger popups or redirects.

Keep ad placeholder rendering controlled by a central configuration, for example:

showDemoAds = true

When showDemoAds is false, remove the development placeholders cleanly without leaving excessive empty gaps.

Prepare the AdSlot component so a developer can later integrate the official Google AdSense code or approved ad-serving mechanism.

Do not invent a publisher ID, ad slot ID, or AdSense script.

Do not load real advertising scripts in development.

The presence of these placeholders does not imply AdSense approval or guarantee that the intended placements are eligible for ads.
